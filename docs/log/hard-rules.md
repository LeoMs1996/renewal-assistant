# 硬规则自检清单（全程适用 · 每个步骤抄一份）

> 建立于 C0（2026-11-17），适用对象：C1–C5 及后续所有理赔域任务、全部子 Agent 与孙 Agent。
> 用法：每个步骤开工时**复制第 3 节模板**到 `docs/log/step-<id>-gate.md`，边做边勾；未勾完不得提交、不得声称完成。

---

## 1. 五条硬规则（不可协商）

### H1 · 动手前必须外部检索 ≥3 个独立来源

- 任何代码/配置/契约的修改，**先检索后动手**；检索结果必须能回答「我凭什么是这样实现的」。
- 「独立」= 不同站点/不同文档来源。同一文档的两个小节只算 1 个来源。
- 优先一手来源（官方文档、规范、原始论文）；教程/博客只能补充，不能作唯一依据。
- **禁止**用模型内置记忆直接实现。若检索后仍无来源支撑，结论必须标注「待验证」，且**不得据此写死代码**。

### H2 · 每条依据必须落盘「URL + 检索时间 + 用途」

- 时间精确到日期（`2026-11-17`），同一来源多次检索记最后一次。
- 「用途」必须写成**支撑了哪条具体决策**（例：「据此选用 `dir/**` + `!` 白名单写法」），不是「参考了」。
- 落盘位置：本步骤的 `docs/log/step-<id>-*.md` 表格；代码注释里只写 `依据见 docs/log/...`，不复制大段外部内容。

### H3 · 全程文档（每步四件套）

每一步必须产出可被别人接手的文档，最少四节：

1. **做了什么**（改动清单：文件 + 一句话职责）
2. **关键决策与依据**（决策 → 来源编号 → 影响；含被否决的方案及原因）
3. **验证证据**（**命令 + 真实输出原文**，不是「测试通过」四个字）
4. **遗留问题与交接**（未做的、已知限制、下一步该谁做）

### H4 · 不碰保护对象（续保基线）

- 保护对象清单见 `docs/log/step-c0-baseline.md` 第 4 节：`server/`、`tests/`、`mcp_servers/test_*.py`、`SPEC.md`、`wiki/`、`traces/`、既有 `eval/cases/`。
- 理赔域只能**新增**；确需复用续保能力时，用「导入 + 参数注入（`TRACE_DIR` / `WIKI_DIR`）」而非改源码。
- 每步结束时 `git diff 40541d1 --stat -- server tests mcp_servers wiki SPEC.md` 必须为空。

### H5 · 数据与轨迹物理隔离

| 理赔域 | 续保域（只读） | 强制手段 |
|---|---|---|
| `traces-claims/` | `traces/` | 运行时 `TRACE_DIR=traces-claims` |
| `data/llm-wiki-claims/wiki/` | `wiki/` | 运行时 `WIKI_DIR=data/llm-wiki-claims/wiki` |
| `data/ins-mmbench/` | `synthetic/` | 只读第三方数据，gitignored |
| `claims/SPEC-claims.md` | `SPEC.md` | 契约分文件，续保 SPEC 只读 |

**任何写入落到上表左侧以外的位置 = 违规。** 首次运行必须用 `ls -la` 或日志里的绝对路径确认落点。

## 4. 违规定义与处置

| 违规 | 判定 | 处置 |
|---|---|---|
| 无外部检索就开始改代码（H1） | 硬违规 | 停止，回滚该改动，补检索后重做 |
| 来源 <3 条，或「用途」为空（H2） | 硬违规 | 文档打回，不得报完成 |
| 只写「测试通过」无原始输出（H3） | 硬违规 | 补齐原始输出 |
| 改动保护对象（H4） | 硬违规 | 立即回滚；C5 直接判失败 |
| 轨迹/知识写入续保目录（H5） | 硬违规 | 删除误写文件 + 修正路径注入 |
| 打印 `.env` / 真实凭证 | 安全硬失败 | 立即轮换凭证，登记事故 |
| 结论无来源但未标「待验证」 | 质量缺陷 | 标注或删除该结论 |

**自检者不得为自己的实现签发通过结论**——交叉验证由另一个 Agent 完成（C5 终验）。

## 5. 为什么是这几条（依据）

- **H1/H2**：禁止用内置过时知识实现，本质是把「实现依据」变成可审计的外部证据。检索纪律的可审计性要求见 `docs/log/step-c0-baseline.md` 第 8 节 S3（OWASP Logging 对 audit trail 与非否认性的讨论）。
- **H3**：同 S3——证据必须是原始记录，而非事后结论。
- **H4/H5**：同 S4（monorepo 以目录边界隔离子域、原子提交）、S5（repository 即 source of truth，基线以 commit + 内容哈希双锚固定）。
- **H2 的白名单写法细节**：同 S1（gitignore pattern 语义与 `!` 例外）、S2（大文件入库上限）。
