# renewal-assistant 全维度架构评估与优化报告

- **评估时间**：2026-11-13（Asia/Shanghai）
- **评估对象**：车险续保助手 renewal-assistant（SPEC v1.0.2，三轮评审验收 6/14 → 13/14 → 14/14）
- **评估方式**：9 个技术域子评估 Agent 独立执行「检索 2026 基准 → 读码对比 → 差距分析与改动项 → 自行归纳」，主 Agent 仅轻量汇总
- **硬性约束遵守声明**：所有评分依据均附来源链接与检索时间戳；无法检索证实的观点标注「待验证」

## 一、总评结论（先行）

**综合评级：6.4 / 10 —— 「演示级超额完成，生产级差一次系统性加固」。**

该项目在**契约纪律与业务正确性**上明显高于典型课程项目：SPEC 唯一契约严格执行升版、三轮评审 6/14→14/14 全程可追溯、确定性评测骨架（22 类断言器 + 独立手算保费复核 + 轨迹回放校验）、PII 双层脱敏带测试断言、报价锁定 MCP 工具服务抑制 LLM 编造。

核心差距集中在四个生产化维度（按影响排序）：
1. **安全**（4.5 分，最低）：全端点零鉴权 + owner_id 自报可枚举他人保单 + /trace 无鉴权暴露含 PII 轨迹（OWASP API1/API2/API4、LLM01/LLM02）
2. **编排基础设施**（7 分）：未用 LangGraph 官方 checkpointer+thread_id 持久化，human-in-the-loop 未用 interrupt()/Command(resume)，放弃 durable execution
3. **可观测性开放性**（6 分）：自有 JSONL 轨迹完成度高但未对齐 OTel GenAI semconv，无法进入 Langfuse/LangSmith 标准面板
4. **工程自动化**（6.5 分）：无 CI、手写 check() 而非 pytest 生态、无 ruff/mypy/依赖锁定

**MCP 协议通道在生产链路形同虚设**（bridge 进程内直连函数，从未经 tools/list、tools/call 验证）是本轮评审发现的最具隐蔽性的 high 风险。

## 二、各子 Agent 评估章节

### 2.1 Agent 编排（LangGraph 状态机）— 7.0

**2026 基线**：LangGraph 1.x 官方 persistence/checkpointers（生产应用应配 checkpointer + thread_id，支持重启恢复/时间旅行）、interrupts（interrupt() + Command(resume=) 为 human-in-the-loop 标准模式）、graph-api-state（Annotated reducer 状态更新语义）。
- 来源：[docs.langchain.com/oss/python/langgraph/persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) · [graph-api-state](https://docs.langchain.com/oss/python/langgraph/graph-api-state) · [checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)，检索于 2026-11-13T01:00–01:02+08:00

**优势**：11 节点单一职责、intake 确定性意图路由、条件边显式声明、步数上限+无进展退出双护栏、轨迹全留痕，业务正确性经 14/14 评测验证，符合官方 workflows+agents 图设计指引。

**关键差距**：
| 严重度 | 发现 | 改动项 |
|---|---|---|
| high | 无 checkpointer，跨轮靠自研 sessions.py JSON 快照 + 整图重入，崩溃在节点中间丢当轮进度 | `compile(checkpointer=SqliteSaver/PostgresSaver)`，session_id 作 thread_id |
| high | await_confirm 用 END+CONFIRM_WORDS 正则识别跨轮重跑，非 interrupt()/Command(resume)，正则易误判 | await_confirm 节点用 `interrupt({quote_id, summary, confirmables})`，/chat 以 Command(resume=…) 续跑 |
| medium | 临时键手工黑名单（_EPHEMERAL_KEYS 22 键）维持跨轮语义 | 显式 SessionState DTO 白名单或交由 checkpointer 托管 |
| medium | State 无 Annotated reducer，quotes 整体替换语义靠注释约定 | `Annotated[list, operator.add]` 声明合并语义 |
| medium | 会话写仅进程内锁 + 非原子覆盖写 | 临时文件+rename 原子替换；多实例迁移 DB checkpointer |

**待验证**：LangGraph 1.2.20 changelog 逐条核对未做；LangSmith 在 GLM 兼容接口下可用性未证实。

### 2.2 MCP 工具服务 — 6.5

**2026 基线**：MCP 官方规范 2026-07-28 版（inputSchema/outputSchema 为 JSON Schema draft 2020-12、structuredContent、isError、Stateful Tools；stdio 凭据走环境变量）、官方 build-server 快速入门（MCPServer Python SDK 2.x 模式、stdio 禁写 stdout、MCP Inspector 验收流程）。
- 来源：[modelcontextprotocol.io/specification/2026-07-28/server/tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) · [authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) · [build-server](https://mcpcn.com/docs/2026-07-28/develop/build-server/)，检索于 2026-11-13T01:04–01:05+08:00

**优势**：SDK 2.x 用法（MCPServer/@mcp.tool/stdio）与官方文档模式一致；stdout 干净；幂等键归一化 + 序号持久化 + 锁保护；保单输出脱敏。

**关键差距**：
| 严重度 | 发现 | 改动项 |
|---|---|---|
| high | **生产主链路绕过 MCP 协议**：mcp_bridge 进程内直调函数，tools/list、tools/call、initialize 从未被验证，SDK/协议升级漂移不可感知 | 增加 stdio 子进程 + 真实 MCP client 的 e2e/CI 用例（可用 Inspector） |
| medium | SPEC §3.2 规则3（版本自增）为死代码，quote_version 恒 1，文实不符 | 实现版本自增或按契约先行原则升 SPEC |
| medium | coverage_selection 为 `list[dict[str,Any]]`，sum_insured 无类型约束 | Pydantic CoverageItem(Literal 枚举) 自动生成强 inputSchema |
| medium | 无 outputSchema；业务错误信封与协议 isError 语义混用 | 补 Pydantic 返回模型或在 SPEC 登记映射关系 |
| medium | 报价登记簿 _QUOTES 进程内存，重启后 24h 幂等失效、旧报价 QUOTE_NOT_FOUND 误伤 | 以 traces/quotes.json 作重启后读源，或 SPEC 声明生存期边界 |
| low | 持久化静默吞错、无 stderr 日志 | logging → stderr，失败记 warning |

**待验证**：SDK 2.3.0 与官方推荐版本对齐情况；多进程写 quote_seq.json 竞态实际发生率。

### 2.3 RAG/条款检索 — 6.0

**2026 基线**：企业级 RAG 为 dense+sparse 混合检索 + RRF(k=60) 融合（Atlan 2026-09 更新）；两段式「混合粗召回 + 神经 rerank」优于任何单阶段（arXiv 2604.01733）；企业 Hybrid RAG 评测要求逐 chunk 接地（arXiv 2609.01617）。
- 来源：[atlan.com/know/hybrid-rag](https://atlan.com/know/hybrid-rag/) · [arXiv 2604.01733](https://export.arxiv.org/pdf/2604.01733) · [arXiv 2609.01617](https://export.arxiv.org/abs/2609.01617)，检索于 2026-11-13T01:01–01:03+08:00

**优势**：citations 带 wiki_id/source/version 全链路落 SSE 与轨迹，可审计性优于多数同类项目；8 条目合成语料下 BM25-only 属可辩护的范围裁剪。

**关键差距**：
| 严重度 | 发现 | 改动项 |
|---|---|---|
| high | 纯 BM25 单路，语义改写问法（"不买车损险行吗"）可能漏召回 | 本地 embedding 两路召回 + RRF 融合，保持离线自包含 |
| medium | 无 rerank 精排，BM25 原始分直接截断 Top-3 | 预留 rerank 接口，eval 补检索命中率验证收益 |
| medium | 摘录为 body 前 160/400 字符位置截断，非相关 chunk；接地只能回溯整条目 | 按 ## 标题分 chunk；轨迹附摘录哈希，eval 加接地断言 |
| medium | 无 Recall@k/MRR 检索层独立评测 | 建最小检索金标集（query→wiki_id），报 Recall@3 |
| low | tokenize 英文重复入票权重翻倍；索引无热更新 | 删逐字符分支；mtime 懒重建 |

**待验证**：Anthropic 官方引用规范正文未抓到；bge-m3 实测效果未验证。

### 2.4 评测体系 — 7.0

**2026 基线**：promptfoo 断言体系（llm-rubric/factuality/cost/latency 一等断言、Red Teaming）；LangSmith 轨迹评测（trajectory matching、LLM-as-judge、多轮模拟、pytest 集成）；评测方差工程实践（多 run 统计、方差阈值）；AEMA 可验证 agent 评测框架（arXiv 2601.11903）。
- 来源：[promptfoo expected-outputs](https://www.promptfoo.dev/docs/configuration/expected-outputs/) · [LangSmith trajectory-evals](https://langchain-5e9cc07a.mintlify.app/langsmith/trajectory-evals) · [评测方差实践](https://github.com/oneuptime/blog/tree/master/posts/2026-08-31-measure-llm-eval-variance-thresholds)，检索于 2026-11-13T00:56–00:59+08:00

**优势**：只读确定性证据（SSE+轨迹+API 三源）、22 类断言器、hard/soft 分级、按 rates.json 独立手算保费复核、报价登记簿快照恢复与轨迹回放校验（AC-14）——回归闭环真实有效，工程纪律高于平均。

**关键差距**：
| 严重度 | 发现 | 改动项 |
|---|---|---|
| high | LLM 模式单次运行无方差统计，幻觉/文本质量无 LLM-as-judge | message 加 GLM judge 断言（rubric 锚定 SPEC 话术）；关键 case n≥3 取通过率 |
| medium | 引用断言只查 wiki_id 存在性，不校验版本一致与内容支撑 | citation.version 确定性断言 + faithfulness 抽样 |
| medium | 报告纯 Markdown，--diff 靠正则解析；runner 恒 exit 0 无 CI 门禁 | 同步落 JSON 报告；加 --ci 开关非零退出 |
| medium | 无注入红队用例、无多轮模拟 | 补 3-5 条注入类 hard case；LLM 模拟用户多轮改需求 |
| low | 无 cost/latency 指标；断言器自身无元测试 | 从 traces 聚合 token/时延；断言引擎补 pytest 元测试 |

**待验证**：OpenAI Evals 官方页 403（经 openlayer 二手核实）；HELM 2026 状态未证实；GLM 实际输出方差幅度需实测。

**关键差距**：
| 严重度 | 发现 | 改动项 |
|---|---|---|

| high | SSE 无心跳、无 id:/Last-Event-ID 断线续传 | 15s `: ping` 保活；关键事件附递增 id 定义重放语义 |

| low | 单进程幂等、order_id random 4 位碰撞面、手写 .env 解析、会话无 TTL | 幂等键哈希/UUID；pydantic-settings；会话过期清理 |

**待验证**：FastAPI 最新版本号来自第三方追踪（newreleases.io）；常驻服务运行时行为未复测（基于静态审读）。

### 2.6 前端 — 6.5

**2026 基线**：MDN EventSource（自动重连语义）；MDN CSP（XSS 转义+CSP 两层纵深）；W3C WCAG 2.2（2026 EN 301 549/EAA 采用）；零依赖单文件 vs 框架工程化取舍（社区工程讨论认可教学场景单文件）。

**优势**：esc() 全覆盖插值（未发现漏点）、token 流走 createTextNode 不经 innerHTML、手写 fetch-SSE 解析器正确处理跨 chunk/注释行/多行 data、confirm 四类错误码逐一映射中文引导、身份切换重置会话防串车主。

**关键差距**：
| 严重度 | 发现 | 改动项 |

| high | 断线即整次失败：无重试/续传，已产出 token 丢失且输入被清空 | 失败保留输入+一键重发；带退避重试或基于 trace 续传 |

| medium | aria-live 挂整条消息列表致读屏碎片播报；动态确认卡无焦点管理；无 prefers-reduced-motion | 流式区与公告区分离；role=status；动画包 reduce 媒体查询 |

| low | 错误 hint 分支转义不一致；零测试零 lint | hintHtml(code) 辅助函数；render 纯函数补 vitest |

**待验证**：真实读屏器体验未实测；「2026 LLM 聊天前端权威行业规范」不存在公认标准（仅厂商 SDK 与社区实践）。

**优势（确认达标项）**：.env 入 gitignore 且 600 权限、零硬编码密钥；PII 双层脱敏（mcp_bridge.py:103 与 quote_server.py:267）带测试断言；合成数据/模拟报价声明全覆盖；/confirm 的 OWNER_MISMATCH 归属校验；保费锁定报价服务架构性抑制 LLM 编造（LLM06 缓解）。

**关键差距**：
