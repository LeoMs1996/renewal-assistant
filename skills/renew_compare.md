# 续保比较技能（renew-compare）

## 触发条件
车主提出续保咨询、保单到期提醒、方案比价或调整险种结构时触发。

## 执行步骤（严格按序）

### 1. 读取原保单
- 调用 MCP 工具 `get_policy`（入参 `owner_id` 或 `vin`），获得：
  车主与车辆信息、当前险种结构、各险种保额/保费、`ncd_factor`、`policy_version`。
- 明确标注到期日，若距到期日 ≤ 30 天，提示"临近到期，建议尽快续保避免脱保"。

### 2. 解析需求
- 从对话中提取：预算意向、保额调整诉求、用途是否变更（网约车等）、是否剔除/新增附加险。
- 识别不可行动作：删除交强险、投保已停售险种（如"发动机进水险"）→ 指出并纠正。
- 信息不足时进入澄清提问，**不得编造**车主信息。

### 3. 获取报价
- 调用 MCP 工具 `query_quote`（入参 `vin` + `coverage_selection`），得到：
  `quote_id`、`quote_version`、`valid_until`（24h 有效）、逐险种保费与总保费。
- 同时取一份"原方案续保报价"作为对照组。

### 4. 保障差异表
输出对照表，逐行：险种 | 原保单（保额/保费） | 新方案（保额/保费） | 差异说明。

### 5. 价格对比
- 总保费对比、差额、NCD 系数变化的影响。
- 用途变更时注明营运系数 1.6 的影响。

### 6. 依据引用
- 每条建议必须引用 `wiki/` 条目（front-matter 的 `id` + `source` 条款名），无依据的判断不得输出。

### 7. 等待确认
- 明确列出待确认项，询问车主："是否按此方案投保？"
- 得到肯定答复前，**不**调用 `POST /confirm`，不生成最终投保单。
- 报价超过 `valid_until` 后须重新 `query_quote`。

## 约束
- 所有引用条款均为虚构合成条款，仅供演示。
- 每一步写入 `traces/` 轨迹（JSONL），字段遵循 SPEC.md。
